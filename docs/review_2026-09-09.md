# PolyTheta review — September 9, 2026

## Fixed and implemented

- Exchange sessions, observed holidays, early closes and DST now drive week IDs, expiry dates, schedules, email checks and expiry modeling. The September 7 Labor Day week was missing in the database; Monday-only scheduling could not recover on Tuesday.
- Current views require the actual current week. Old published baskets no longer masquerade as this week's basket or fall back to demo data when the live database is present.
- Data imports validate source dates, current option expiry and cohort freshness. Failed/missing Yahoo records retry; TradingView macro inputs come directly from FRED/Cboe. The weekly universe refreshes from Cboe. Numeric macro defaults no longer hide outages.
- Modeled market refresh prioritizes current-week positions, rotates bounded batches and aborts slow reads before the scheduled function's timeout. Price failures do not suppress independent news checks. This is separate from the IB worker's live portfolio monitoring.
- Basket imports are atomic and preserve existing positions, snapshots and audit history. Delayed email delivery retains its original price/source timestamps and cannot cross into another week.
- Allocation is a configurable equity percentage split equally across whole trades. Call/put percentages determine counts, with configurable maximum trades. Default calls100%, puts0%; no doubling. TSLA and SPCX/SpaceX are excluded by default and editable.
- Per-ticker/side/expiry minimum OTM settings apply in strike selection and at live entry. Delta/ATR rules remain in force. Changing a minimum never edits an existing holding.
- TWS and Web API adapters share deterministic execution rules. They resolve exact contracts and price increments, require real-time execution quotes, request margin previews, preserve intent before submission, reconcile partial fills, and avoid blind write retries.
- Actual holdings, fill costs and IB marks are displayed separately from modeled results. Only attributable PolyTheta trades contribute to P/L and owner-confirmed Exit NOW / Exit all NOW controls. Account fingerprints bind confirmations to the account shown. Exit all pauses entries and includes fills received after the displayed snapshot.
- GSRS is unchanged and visible at `/trading-rules`, including all normalizations, clipping, weights and rounding. Basket GSRS is an entry snapshot, explaining part of its apparent stability.
- Next.js was updated to16.3.4 and compatible vulnerable dependencies were patched. The production dependency audit reports zero vulnerabilities. Four moderate development-tool advisories remain in the Drizzle/tsx esbuild dependency graph; npm's proposed forced fix downgrades Drizzle across breaking versions and was not applied.

## Boundaries and remaining verification

- The local read-only check could not authenticate: `IBKR_ACCOUNT_ID` is not configured, and the standard live Gateway/TWS ports had no listener. Owner execution-host selection, gateway authentication, market-data entitlements and contract/margin read checks remain outstanding. No live orders or activation occurred.
- Pre-existing manual PolyTheta trades need broker-evidence reconciliation before adoption. The code does not infer ownership from a ticker match or adopt all account positions.
- Expiry/assignment without a closing execution requires authoritative IB activity-statement reconciliation. The code flags missing settlement evidence; it does not invent a zero-cost close or act on unattributed stock assignments. Historical Flex statement import is not yet automated.
- News coverage is limited to the configured feed and recognized trusted sources. No code can establish that every acquisition rumor was seen. Apify was not required for the verified data paths and was not subscribed to or activated.
- Legacy modeled history retains prior sizing assumptions. At least one July13 source proposal was generated on July16; this is a historical timing concern, not evidence of achievable entry prices. No historical performance records were silently rewritten.
- The reviewed exchange calendar covers2025–2028. Review new exchange announcements and extend the verified horizon before2029.
